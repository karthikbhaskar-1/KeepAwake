# KeepAwake - roadmap

Written 2026-11-03. Current release: 1.2.0. Background and measurements: [FINDINGS.md](FINDINGS.md).

## Principles that every version keeps

- One exe, no installer, no admin, no network, no telemetry. Target under 1 MB; today 155 KB.
- .NET Framework 4.8 so Windows 10 1903+ and Windows 11 run it with nothing to download.
- Nothing ticks while nothing is pending: 0.000% CPU in the tray stays a release gate.
- The custom look stays; new UI reuses the existing painted controls.
- Every feature that writes outside the exe folder (registry, Start Menu) is opt-in and documented.

## 1.3 (proposed)

Small, safe items that remove the most common friction. Effort: S under a day, M a few days, L a week or more.

| # | Feature | Why | Effort |
|---|---|---|---|
| 1 | System-only mode: keep the PC awake but let the display sleep (drop ES_DISPLAY_REQUIRED). Options menu toggle | Downloads and builds do not need the screen on; saves power on laptops | S |
| 2 | Idle guard: after N hours without real input (GetLastInputInfo), balloon "Still needed?"; stop if unanswered after 10 minutes | Protects against a forgotten Forever | S |
| 3 | Smarter simulation: nudge only when the user is idle, and an F15 key press option for remote desktop sessions that ignore mouse moves | Fewer visible jitters, works over RDP | S |
| 4 | Command-line verbs `--for 2h`, `--until 17:30`, `--forever`, `--off`, `--quit`, forwarded to the running instance | Scriptable from shortcuts, Task Scheduler and build scripts | M |
| 5 | winget and Scoop manifests generated by CI on release | Easy install and update while staying portable | S |
| 6 | Resume detection: after sleep or hibernate, re-assert the hold and report how long it was lost | Correctness after lid-close events | S |

## 2.0 (needs a decision from the owner)

| Feature | Why | Blocker |
|---|---|---|
| Code signing (Azure Trusted Signing or SignPath for open source) | Removes the SmartScreen warning, the main adoption barrier | Needs an account and identity verification by the owner |
| Start with Windows, opt-in (HKCU Run value, removed when toggled off) | Often requested | Conflicts with "no registry writes"; must stay opt-in |
| Localisation with an embedded string table | Wider audience without extra files | Translation effort |
| Calendar-aware "until end of meeting" via Outlook COM | The most common real reason to keep a PC awake | Only works with desktop Outlook installed |
| Native splash stub (C++) painting before the CLR loads | Only if start-up ever misses the 200 ms target | Second toolchain in CI |

## Process for each version

1. Spec in `docs/SPEC_<version>.md` (what, why, settings keys, menu layout, tests to add).
2. Implementation with tests; build must have 0 warnings; all tests pass.
3. Independent review of the diff written to `docs/REVIEW_<version>.md`; fixes for every High and Medium, Low where small.
4. Verification on a real machine: scripted UI run, performance script (CPU, memory, GDI), screenshots.
5. Version bump, commit, tag `v<version>`; CI builds, tests, size-gates, hashes and publishes the release.

## Not planned

- Any form of installer, service, or background updater.
- Telemetry, crash reporting to a server, or network access of any kind.
- Replacing the custom-drawn UI with a framework that needs a runtime download.
